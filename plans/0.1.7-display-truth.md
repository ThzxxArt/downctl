## 2. 通读结论：现在的"进度"错在哪里

### 2.1 实机证据（伪终端，120×40，3 个 12 MiB 文件，`-j 3`）

0.1.6 的真实输出（节选）：

```

total (3 files):  88%|███████████████████████████▍  | 31.7M/36.0M [00:16<00:02, 2.02MB/s]
```

## 3. 主题与设计原则

**主题：呈现的真相。** 进度不是装饰，是运行状态的一份可核对声明。每条声明都要满足：

1. **一个写者、一个区域。** 只有 ticker 画帧；所有人类消息先清区、打印、再恢复。
   reporter 回调只更新数字，不做 I/O。
2. **不知道就说不知道。** 未知大小 → `--%` / `--:--`；没有近 3 秒样本 → `--`；
   有未知任务时不给整批 ETA；续传种子只算一次；重试/校验时隐藏过期速率。
3. **状态比装饰重要。** `retrying in 5s (attempt 2, HTTP 502)`、`verifying sha256`、
   `skipped (already complete)` 比多一格动画有用。
4. **观察者不得失败下载。** reporter 的每个公开回调自吞异常并降级；
   新增呈现事件用 `call_optional_safe`；`Ctrl-C` / 异常 / 退出都恢复光标。
5. **终端能力按证据降级。** TTY + 非 `dumb` → 活块；显式 `live` 遇管道 → 周期行；
   非 TTY 默认仍静默（不破坏 `downctl get | ...`）；`NO_COLOR` 只关颜色。
6. **契约只加不改。** Reporter 三个必选方法不变；旧式 reporter（无 `**kwargs`）继续工作；
   `--reporter tqdm` / `json` / `quiet` 名字不变；JSON 事件名与字段不删。

### 3.1 兼容边界（必须保住）

| 契约 | 0.1.7 的处理 |
|---|---|
| `--reporter json` 独占 stdout、逐行 JSON | 不动；新增 `--progress` 不覆盖显式 reporter |
| JSON 事件/字段（`run_start`/`start`/`progress`/`resume`/`finish`/`failure`/`run_finish`/`dry_run`） | 不删不改；新呈现事件**不进** JSON reporter |
| tqdm 三段文案 | 保留 `tqdm` 插件与测试；仅修跨作业条泄漏 |
| `-q` 不吞命令结果 | 不动；`-q` 仍优先于隐式 `--progress` |
| 非 TTY 默认静默 | `auto` 保持 quiet；`--progress plain` 显式选择日志行 |
| reporter 三方法 | 不变；新增方法全部可选、`getattr` 探测、按签名过滤 |
| `[plugins.tqdm] enabled` | 仍是兼容开关：显式 false 在 `auto` 下仍表示"不要进度" |

## 4. 信息架构

### 4.1 单文件

```
⠸ downloading file1.bin
[████████████▋░░░░░░░░░░░░░░░░░░░░░░░░░░░]  31% · 3.8 MB/12.0 MB · 1.9 MB/s · ETA 00:04
```

一条状态行 + 一条数字行。不再为同一个文件画两根条。

### 4.2 多文件

```
⠼ downloading · 3 files · 34.7 MB / 36.0 MB · 1.9 MB/s · ETA 00:01
[██████████████████████████████████████▌░]  96%  0/3 done · 3 active
  ↻ file3.bin  retrying in 5s (attempt 2, HTTP 502)
  ▶ file1.bin  11.6 MB/12.0 MB   96%  668.9 KB/s  ETA 00:01
  ▶ file2.bin  11.4 MB/12.0 MB   95%  646.6 KB/s  ETA 00:01
```

- 总条只出现一次；每行一个工作文件；重试/校验行优先于普通活动行。
- 已完成文件折叠为计数（`2/3 done`），失败文件在本次运行内保留一行，跳过计入 `skipped`。
- 行数受终端高度约束；超出的活动文件折成 `… 3 more active`。

### 4.3 窄终端（40 列）

```
⠋ downloading · 3 files
[███▎░░░░░░░░]  27%  1/3 done · 2 active
  ↻ file3.bin  retrying in 5s (attempt …
  ▶ file1.bin   47%
```

逐级丢弃：每文件 mini 信息 → ETA → 速率 → 字节数 → 整批 bar；状态词、百分比、
文件名永远保留。

### 4.4 探测 / 校验 / 重试

```
⠦ preparing 3/10 targets
[████████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░]  30%

verifying image.iso
[████████████████████████████████████████] 100% · 4.2 GB/4.2 GB
  sha256
```

### 4.5 非 TTY / CI（显式 `--progress plain`）

```
downctl:  45%  16.2 MB/36.0 MB  1.9 MB/s  ETA 00:12  2/3 done  1 active
downctl: failed file3.bin (permanent)
```

每 15 秒一行 + 每个失败/跳过立即一行；不写 ANSI。默认 `auto` 在非 TTY 仍保持
0.1.6 的静默，避免改变管道语义。

## 5. 架构

### 5.1 新模块

```
src/downctl/
├── progress/
│   ├── text.py       # 单元格宽度、截断、bar、人类格式
│   ├── model.py      # RunView / TaskView / Rate：可观测状态
│   ├── render.py     # 纯函数 (RunView, RenderOptions) -> list[str]
│   └── terminal.py   # 唯一持有流、光标、清区/恢复
├── builtin/reporters/live_reporter.py  # LiveReporter + PlainReporter
└── plugin/callbacks.py                 # 可选回调的签名过滤与安全调用
```

职责边界：`model` 不知道终端，`render` 不知道流，`terminal` 不知道业务，
`live_reporter` 只做事件 → 状态 → 何时画。

### 5.2 事件流

```
app._run_plan ──phase(resolve/probe)──┐
engine.download_all ──run_started─────┤
engine.download_task ──task_started───┤
transfer chunk ──task_progress(delta)─┤──> RunView ──> render() ──> Terminal
engine retry ──task_retrying──────────┤         ▲
engine verify ──task_phase("verify")──┤         │ 8 fps ticker（异步，单写者）
engine skip/restart ──task_restarted───┘         │
console.warn/error ──writing() 清区/恢复────────┘
```

- `task_progress` 只做整数加法与 `deque.append`；绘制由 ticker 决定，下载热路径不写终端。
- ticker 在 `run_started` 创建、`run_finished` 取消；同步调用（测试/库用户）退化为
  “回调内按 fps 节流画”。
- `console.attach_live(terminal)` 让所有现有 `console.*` 写入自动清区/恢复；
  `Ctrl-C`/异常由 `_guard` 的 `finally: console.reset_live()` 兜底。

### 5.3 可观测状态

`RunView` 只依赖 reporter 能拿到的数据：任务数、声明总字节、`jobs`、未知大小任务数、
`job` 名、每任务 `size`、`received`、`resumed`、`ok/failure/witness/skipped`，
以及新增的可选事件。**不猜** piece 网格、连接数、每连接吞吐——这些仍在 transfer 内部；
0.1.7 不为了显示而侵入热路径。

### 5.4 选择优先级

```
--reporter NAME（显式）
  > -q/--quiet
  > --progress MODE
  > [core] progress
  > auto
```

| 条件 | auto 结果 |
|---|---|
| stderr 是 TTY、`TERM != dumb`、`[plugins.live] enabled` | `live` |
| `[plugins.live] enabled = false` 且 tqdm 未禁用 | `tqdm`（兼容） |
| `[plugins.tqdm] enabled = false` | `quiet`（0.1.6 的显式关闭语义） |
| 非 TTY / `TERM=dumb` | `quiet` |
| `--progress live` 但非 TTY | `plain`（不能把光标转义写进日志） |

`NO_COLOR` 不参与此表；它只决定 `color_enabled()`。

### 5.5 配置

```toml
[core]
progress = "auto"        # auto | live | plain | off

[plugins.live]
# fps = 8
# unicode = "auto"       # auto | always | never
# color = "auto"         # auto | always | never
# plain_interval = 15

[plugins.tqdm]           # 0.1.6 的默认，保留为显式选择
enabled = true
```

`--progress` 与 `[core] progress` 使用同一组值；非法值在配置加载或选择时直接报错，
不静默回退。

## 8. 兼容与迁移

### 8.1 用户可见变化

1. **TTY 默认从 tqdm 改为 live 块。** 外观变了，语义更丰富；`--reporter tqdm` 可回到旧外观。
2. **`NO_COLOR` 不再关闭进度。** 这是缺陷修复，不是新行为；只影响此前"无色即无进度"的
   环境。
3. **非 TTY 默认仍静默。** 需要日志进度时显式 `--progress plain`。
4. **`--progress` 与 `[core] progress` 新增。** 旧配置无需迁移。
5. **`[plugins.tqdm] enabled=false`** 在 `auto` 下仍表示"不要进度"；`[plugins.live] enabled=false`
   回退到 tqdm。
6. **reporter 协议只增不减。** 旧插件不实现新方法即可；新方法按签名过滤，不传未声明的
   keyword。

### 8.2 退役/保留

- `tqdm` reporter **保留**（显式选择、JSON/quiet 不变），不在 0.1.7 删除依赖。
- `_call_with_job` **退休**，签名过滤的唯一属主迁到 `plugin/callbacks.py`。
- `tqdm` 的跨作业条泄漏修复；不改变文案断言。

## 9. 风险与不做

| 风险 | 等级 | 缓解 |
|---|---|---|
| 终端差异（Windows 旧控制台、字体缺块） | 中 | `unicode=auto/never`、ASCII 回退、`init_console` VT 已有；Windows 真机未验，文档标注 |
