# downctl 0.1.5 迭代方案 —— 传递（Carry）

> 状态：**待批准**。本文只提方案，未修改任何受版本控制的文件。
> 基线：`v0.1.4` @ `eb4d1b0`（2026-10-18，**已上 PyPI**，`latest`）
> 依据：**156 个受版本控制文件 / ≈28,900 行逐行通读**（附录 B）+ 全量测试
> （`750 passed` / `92.50%` / 145s）+ **六个已执行的复现实验**（附录 A）。

**Aegis Visibility**：本方案要一份持久文档，是因为它同时触碰
**一次请求的授权边界**（凭据能发给谁、代理能作用于谁）、
**一次数据写入的同一性**（源与目标是不是同一个文件）、
与**一条证据链的完整性**（引擎算出的 witness 有没有抵达写证据的人）。
三者单独都可以走轻量路径；三者共用同一个根因时，必须先固定边界。

## 2. 分析：根因是"意图在传递中丢失"

0.1.3 让账本知道"哪个 URL"，0.1.4 让账本知道"哪个版本"。两次都在解决
**状态 ↔ 对象**的关系，而且都做对了。

本轮通读与六个实验发现的问题，是另一种形状：**一个决定被做出之后，没有抵达真正执行它的那一行；
或者抵达了，但途中被重新猜了一次。**

| 决定 | 谁做的 | 谁该执行 | 实际发生了什么 |
|---|---|---|---|
| "这个目标需要这个 token" | source 插件 → `DownloadTask.headers` | 传输 ✅ / **探测 ✗** | 探测用共享 session，401 |
| "用户要求走这个代理" | 用户 `-p` / 环境变量 | 所有请求 | **把"猜出来的"当成"用户要求的"**，回环也被代理 |
| "这个 token 属于哪台主机" | 用户配置的 `token` | 签发主机 | 配置了 `mirror` 就发给 mirror |
| "这份字节凭什么算完成" | 引擎 `task.meta["witness"]` | 写证据的钩子 | 钩子只看 `ok`，witness 无人消费 |
| "hook 的 `events` 是列表" | `Hook.__init__` 归一化 | 事件过滤 | `setattr` 绕过 `__init__`，字符串退化成子串匹配 |
| "探测失败的原因" | 后台线程 | 用户 | 异常被 `gather(return_exceptions=True)` 吞掉 |
| "我要原始字节" | `Accept-Encoding: identity` | aiohttp | **aiohttp 的解压只看响应的 `Content-Encoding`**，这个头关不掉它 |
| "源文件和目标是同一个 inode" | 没人 | 传输 | 没有 `samefile` 检查 |
| "这次没有重下" | 测试夹具 | 断言 | `seen_ranges()` 过滤 `None`，整包重下不可见 |

一句话：**0.1.4 把"字节的真相"修干净了，但没有修"决定的旅程"。**
0.1.5 的主题就是让每一个决定抵达它该抵达的那一行。

## 3. 已实证的缺陷（玥玥亲手复现，附录 A）

### C-1 探测丢弃任务凭据 —— 0.1.4 引入的回归

**代码**：`_probe_task` 调用 `probe_metadata(ctx.session, task.url)`，`task.headers` 从不传入
（`app.py:905,908`）；`probe_metadata` 也没有 `headers` 参数（`probe.py:141`）。
同一缺陷在两条恢复路径上重复：`engine._witness_changed_again`（`engine.py:931`）、
`_reprobe`（`engine.py:949`）。

**为什么是回归**：0.1.3 的 `_probe_task` 在 `task.size > 0` 时早退，而 HF/GitHub 恰好都给出大小
—— 它们**从不被探测**。0.1.4 为让所有目标都有见证删掉了这道门（记为修复项），
于是每个带凭据的目标第一次被一个没有凭据的请求审视。

**实证 A.1（进程内）**：

```
task.headers = {'Authorization': 'Bearer s3cr3t'}
PROBE FAILED  : PermanentHTTPError: HTTP 401 for http://127.0.0.1:.../private.bin
TRANSFER WOULD: HTTP 200, 10000 bytes, matches=True
```

**实证 A.2（完整 CLI，假 Hub 强制 token）**：

```
exit code      : 1
stderr         : downctl: error: HTTP 401 for http://127.0.0.1:.../acme/private/resolve/main/w.bin
file downloaded: False
failed log     : url  http://.../w.bin  w.bin  7500  huggingface  hf://acme/private  permanent
```

**后果**：私有 HuggingFace 仓库、私有 GitHub asset、任何依赖 `DownloadTask.headers` 鉴权的
第三方 source，在 0.1.4 上都会在传输前被判 `permanent`。README 把"私有仓库需 token"写成功能
（`README.md:455,482`），现在不成立。

**严重度：Critical**（回归 + 文档承诺的功能失效）。

### C-2 猜测出来的 WSL 代理作用于回环地址

**代码**：未显式配置代理时 `app._build_config` 调 `detect_wsl_proxy("")`（`app.py:244-252`），
后者在 WSL 下取 `/etc/resolv.conf` 的 nameserver 拼成 `http://<ip>:7897`
（`platform_utils.py:213-230`，端口硬编码），`make_session` 把它作为 `proxy=`
交给 aiohttp（`session.py:63-64`），aiohttp 对**所有**请求使用它。

**实证 A.3**：

```
[默认(WSL自动探测)]        exit=1  status=unreachable
[WSL_HOST_IP=127.0.0.1]   exit=0  status=200  size=4 B
```

**后果**：这台机器上对 `http://127.0.0.1:...` 的下载默认不可用；更一般地，
只要宿主没在 7897 监听，WSL 下**所有**下载都失败，错误是
`Cannot connect to host 10.255.255.254:7897` —— 用户无法从中推断"downctl 自己猜了个代理"。

**严重度：High**（把"未配置"变成了"配置了一个可能不存在的代理"，并对本地目标做错误路由）。

### C-3 HF token 被发给 mirror 主机

**代码**：`host = options.get("mirror") or DEFAULT_HOST`（`huggingface_source.py:62`），
`auth_headers` 同时用于 Listing（`:78`）与每个 `DownloadTask.headers`（`:125`），
下载 URL 也由同一个 `host` 拼出（`:103`）。docstring 写 "sent to the HuggingFace host only"（`:12-13`），
`sources.md:48-51` 写 "Sent only to the HF host"。

**实证 A.2**：假 Hub 同时扮演 `mirror`，它对 `Authorization` 做精确匹配才返回 200；
listing 成功这一事实本身证明 **token 抵达了 mirror 主机**。

**严重度：High（安全）**。触发条件：配置了 `mirror` + 环境里有 `HF_TOKEN`（CI 与很多开发机的默认状态）。

### C-4 发布物包含一句仓库自己能证伪的陈述

`CHANGELOG.md:19-20`（`[0.1.4]` 段内）：

> "The tag was never published, so nothing here describes behaviour that ever shipped"

事实：该句在被打的 commit 内（`git diff v0.1.4` 为空）、tag 是 annotated、
PyPI `0.1.4` 上传于 `2026-10-18T07:48Z`。写作当时为真（复审在 tag 之前），
但被打进了发布产物，于是**发布物对一个事实说了假话**——正是本项目反复在修的那类问题。

同源的第二个事实：0.1.3 **把静默拼接缺陷发上了 PyPI**，而它的 changelog 写着
"can no longer splice old pieces into the new file"（`CHANGELOG.md:378-379`）。
0.1.4 只以"升级会重启一次"轻描淡写，**没有 advisory、没有 yank、没有告知 0.1.3 用户
手里的文件可能是拼的**；更麻烦的是 0.1.4 **仍然信任 0.1.3 写的标记**
（`pieces.py:459-509` 的宽松规则），受影响用户收不到任何信号。

**严重度：High（诚信）**。

### C-5 `file://` 源与目标指向同一文件时没有检测

**代码**：`src` 全量搜索 `samefile` / `st_ino` 比对 **零命中**；`_resolve_target` 只做"目标在 `-d` 之内"的越界约束
（`engine.py:161-178`），方向是防越界，不防自指；`file_source._task` 也没把源路径写进 `meta` 供引擎校验。

**实证 A.5**（三种情形，实测）：

| 情形 | 结果 |
|---|---|
| `get file:///tmp/segtest/a.bin -d /tmp/segtest` | **无害**：文件已可证明完整，传输直接短路（`done: 1/1`，字节不变） |
| 同上 **`--force`** | **毁源**：16000 字节 → **0 字节**，随后进入退避重试循环（25s 时仍在重试） |
| 源是**部分文件** + 伪造位图 | 普通路径正常完成、字节不变；但真正"只有半个文件"的情形会陷入无法完成的重试（源就是被写的文件，永远补不齐） |

**更正记录**：独立通读报告把这条描述为"普通 `-d` 自拷贝就会清空源"。玥玥实测**不成立**
——普通路径会因为文件已完整而短路。真实触发面是 `--force` 与部分文件，比原描述窄，但仍然存在。

**后果**：`file://` + `-d` 指向源目录（docstring 自己推荐的"复制到另一个目录"`file_source.py:5-6`
在写错目录时就变成这个场景）会让 `--force` 造成**不可逆数据丢失**。

**严重度：High**（唯一不可逆的数据丢失路径）。

### C-6 基线测量

`750 passed / 145.42s`；`92.50%`；`pieces 99% / transfer 100% / engine 98%`。

## 4. 代码已核实、尚未端到端复现的缺陷

标注为"待证"的项，方案里只做**设计决策与回归计划**，不当作已发生的故障来陈述。

| # | 缺陷 | 证据强度 | 属主 |
|---|---|---|---|
| S1 | **证据钩子为未证实的完成背书**：`checksum_hook` / `manifest_hook` 只看 `ok`，不看引擎已放进 `task.meta["witness"]` 的三态；一个 `witness=none` 的 skip 也会得到 `.sha256` 边车/清单，日后 `--checksums` 用它复验会通过 | 代码路径确认（`checksum_hook.py:43-58`、`manifest_hook.py:33-41` + `engine.py:612-640`），未端到端复现 | hook 层 |
| S2 | **线程化钩子的异常被静默丢弃**：四个钩子把工作丢给 `to_thread`，`add_done_callback(self._pending.discard)` 不取异常；`EventBus.aclose` 用 `gather(return_exceptions=True)` 且不打印 → 加密 zip、损坏 `.tar.xz`、`timeout="300"` 都会"零输出" | 代码路径确认（`plugin/hooks.py:60-72` + 四个钩子） | hook 层 |
| S3 | **hook 配置用 `setattr` 注入，绕过 `__init__` 归一化**：`events = "on_finish"`（TOML 写成字符串）退化成**子串匹配**，`"on_finish" in "on_task_finish"` 为真 → 在错误事件上触发；拼错的键被 `hasattr` 静默丢弃 | 代码路径确认（`app.py:316-320`） | app |

### 4.1 两条被证伪的报告（照实记录）

独立通读报告中有两条，玥玥实测**不成立**，不进入方案：

1. **"`-v --reporter json` 会污染 stdout"**（hooks 报告 D5）。实测输出六行**全部是合法 JSON**，

2. **"普通 `file://` 自拷贝会清空源文件"**（sources 报告 C-1）。实测普通路径**无害**（见 §3 C-5）。

## 5. 变更必要性

- **C-1 不能只改文档**：删掉"私有仓库可用"等于承认功能丧失，而它是 0.1.4 **自己引入**的。
- **C-2 不能只把端口做成配置**：问题不是端口号，是"猜"被赋予了决定所有请求路由的权力。
- **C-3 不能用"别配 mirror"当解法**：镜像在国内是刚需；正确做法是**凭据按签发主机归属**。
- **C-5 不能只写"别把 `-d` 指向源目录"**：这恰好是 docstring 推荐用法的一个笔误，需要一个硬失败。
- **C-4 不能只删一句**：发布物由 CHANGELOG / PyPI 长描述 / sdist / Release notes 多份材料组成，
  任何一份都可能脱钩，需要机械校验。
- **最小代码边界**：不新增插件类别、不改 `Transport`/`Source` 协议、不提升 `API_VERSION`、
  不 bump 状态格式版本。改动集中在 `probe_metadata` 签名 + 3 个调用点、`session.make_session`、
  两个源插件的凭据注入点、`_resolve_target` 的同一性检查、以及文档与门禁。

## 6. 波及面三角

本次触发信号：**契约 / 安全 / 数据同一性 / 门禁**。

| 面 | 现有唯一属主 | 本次影响 | 下游消费者 |
|---|---|---|---|
| `probe.probe_metadata` | `probe.py` | 追加关键字参数 `headers`（默认 `None`） | `_probe_task`、`_witness_changed_again`、`_reprobe`、`probe_size/resource`、第三方调用者 |
| `DownloadTask.headers` 语义 | `core/task.py` + 各 source | 从"传输用的头"扩为"**这个目标需要的全部请求头**" | transfer（已用）、probe（新增）、engine 恢复探测（新增） |
| 代理决策 | `platform_utils.detect_wsl_proxy` + `app._build_config` + `session.make_session` | 新增"代理来源"判别；只有**猜出来的**才被抑制 | 所有 HTTP 请求 |
| 源/目标同一性 | `engine._resolve_target` | 新增 `samefile` 硬失败（仅 `file://` 任务） | `file` 源的复制用法 |
| 证据（witness） | `engine._failed` / `_download_locked` | 已有 `task.meta["witness"]`，新增**被钩子消费** | `checksum`/`manifest` 钩子 |
| `CHANGELOG` / `pyproject` / `workflows` | 仓库根 | 新增机械校验 | 发布门 |

**关键结论：不需要提升 `API_VERSION`，不需要 bump 状态格式。** 新参数有默认值；
`Transport`/`Source` 协议不变。风险被控制在"单进程行为 + 发布材料"。

## 7. 版本主题与目标

> **0.1.5 —— "传递（Carry）"**
> 0.1.3 让账本知道"哪个 URL"，0.1.4 让账本知道"哪个版本"。
> 0.1.5 要让每一个**决定**——凭据、代理、内容身份、见证、失败——都被带到
> **真正执行它的那一行**：不在半路丢掉，也不在别处重新猜一次。

**可判定的版本目标（全部为可执行断言）**

1. 一个要求 `Authorization` 的目标，其探测请求必须带上 `DownloadTask.headers`；
   移除传递后回归变红。
2. 完整 CLI 下私有 HF 仓库（fake mirror 强制 token）**能下载成功**；修复前
   `exit 1` + `.downctl.failed` 记 `permanent`。
3. 配置了 `mirror` 时**默认不向 mirror 发送 `Authorization`**；显式开启后才发；两种都有回归。
4. WSL 未配代理时，对 `127.0.0.1` 的下载**不需要** `WSL_HOST_IP` 也能成功；显式 `-p` 仍作用于所有目标。
5. `file://` 任务在源与目标为同一文件时**必须硬失败**（而不是 `--force` 后把源截断为 0）。
6. `witness=none` 的完成**不得**产出"可被 `--checksums` 消费的证据产物"，或该产物必须自标"未验证"。
7. `CHANGELOG` 的已发布段落中不得出现可被仓库事实证伪的发布状态陈述，由测试机械校验。
8. `pyproject` 声明的覆盖率能力（`patch = ["subprocess"]`）在 dev 环境**确实生效**，否则 CI 失败。
9. `release.yml` 发布前必须验证"tag 在 master 上、CI 绿、CHANGELOG 有对应段"。
10. 上述 1–9 全部有回归，且移除守卫时变红。

## 8. 任务分解

> 每项含：目的 / 最小改动边界 / 兼容性 / 验收 / 风险与工时（一人全职）。

### P0 —— 阻断级（正确性、安全、数据丢失）

**T1 探测继承任务的请求契约**

- **改动**：`probe_metadata(session, url, *, headers=None)`，HEAD 与回退的 ranged GET 都合并该头
  （`Accept-Encoding: identity` 由自己先设，用户头不得覆盖）；`_probe_task` 传 `task.headers`；
  `engine._witness_changed_again`、`_reprobe` 同样传；顺带给探测一个自己的超时
  （`PROBE_TIMEOUT` 默认 30s，受 `--max-time` 夹紧）。
- **兼容**：新参数默认 `None`，`probe_size/resource` 不传即旧行为。
- **验收**：`tests/integration/test_request_parity.py::test_a_credentialed_target_is_probed_with_its_own_headers`
  + `::test_a_private_repository_downloads_end_to_end`；把 `headers=task.headers` 改回不传 → 两条红。
- **风险**：低（多传一个 dict）。工时：0.5 天 + 0.5 天测试。

**T2 凭据按签发主机归属**

- **改动**：HF 在 `host != DEFAULT_HOST` 时默认**不带** `Authorization`，新增
  `[plugins.huggingface] token_to_mirror = false` 作为显式开关；Listing 与 `DownloadTask.headers`
  共用同一判定（单一属主）。
- **兼容**：默认更安全；文档三处（`sources.md` 中英、`troubleshooting.md`）必须写明。
- **验收**：`::test_the_hf_token_is_not_sent_to_a_configured_mirror` + `::test_the_hf_token_reaches_a_mirror_when_explicitly_allowed`。
- **风险**：中（默认行为变化，错误信息要点名该配置键）。工时：1 天。

**T3 代理只作用于它该作用的目标**

- **改动**：`CoreConfig` 增加内部字段记录来源（`explicit`/`env`/`wsl-guess`，不落配置）；
  `make_session` 接受一个按目标 URL 决定用不用代理的策略值对象（属主仍在 `app`）；
  规则：`wsl-guess` 来源时，`127.0.0.1`/`::1`/`localhost`/链路本地/`no_proxy` 命中 → 不用代理；
  `explicit`/`env` → 一律使用。
- **验收**：`::test_a_loopback_target_is_not_routed_through_a_guessed_proxy`（在 `detect_wsl_proxy`
  返回不可达地址时对 `127.0.0.1` 仍 `exit 0`）+ `::test_an_explicit_proxy_still_applies_to_every_target`；
  删掉抑制逻辑 → 第一条红。
- **风险**：中（改动请求路由；`-p` 路径必须零回归）。工时：1 天 + 0.5 天测试。

**T4 源与目标同一文件必须硬失败**

- **改动**：`file_source._task` 写 `meta["source_path"]`；`engine._resolve_target` 在
  `task.source == "file"` 时对解析后的目标做 `os.path.samefile`（或 `st_dev/st_ino` 比较），
  相同即 `DownctlError`（**在任何 truncate/discard 之前**）。
- **兼容**：只影响"源与目标同一文件"这一种错误用法。
- **验收**：`::test_a_file_source_that_is_also_the_target_is_refused`（含 `--force`），
  修复前 `--force` 把源截断为 0；删除检查 → 红。
- **风险**：低。工时：0.5 天。

**T5 证据钩子不得为未证实的完成背书**

- **改动**：`checksum_hook` / `manifest_hook` 消费 `task.meta["witness"]`：
  `none` 时**不写**产物（或写到 `.unverified` 后缀并在文档说明）；`validator`/`checksum`
  时照常写。`manifest` 额外记录 witness 与 identity。
- **理由**：0.1.4 建立了"未证明即报告"，但两个写证据的钩子把这套三态丢掉了。
- **验收**：`::test_checksum_hook_does_not_vouch_for_an_unverified_completion` /
  `::test_an_unverified_completion_is_not_listed`；把 witness 判断删掉 → 红。
  （草案名为 `..._for_an_unversioned_skip` / `..._skips_unverified_entries`；实施时按
  实际覆盖面改名，行为未变。）
- **风险**：低（但会改变既有用户行为，需写进 `upgrading`）。工时：0.75 天。

**T6 钩子失败必须可见**

  `console.warn`；`aclose` 的 `gather` 逐个检查并汇报；`on_finish` 载荷增加 `hooks_failed`；
  可选 `[core] strict_hooks`（默认 `false`）让后处理失败反映到退出码。
- **兼容**：默认只增加可见性，不改变退出码。
- **验收**：`::test_a_broken_archive_is_reported_and_counted`（加密 zip；草案名
  `::test_a_failing_archive_hook_is_reported`，实施时按实际覆盖面改名）+ `::test_a_hook_that_raises_in_a_thread_is_not_silent`。

```

- Expected Retired: 猜出来的代理决定回环/内网请求的路由

```
